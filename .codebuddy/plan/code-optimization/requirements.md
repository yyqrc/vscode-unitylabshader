# 代码性能优化与冗余模块清理 - 需求文档

## 引言

本需求文档旨在优化 Unity Shader 语言支持插件的**运行时性能**，通过识别和清理冗余模块、优化算法复杂度、减少不必要的计算开销，显著提升插件的响应速度和执行效率。经过对项目的全面分析，发现了一些影响性能的关键瓶颈和可优化点。

### 项目现状
- **总代码文件**: 约 30+ 个 TypeScript 文件
- **主要模块**: hlsl、unity、unreal、analysis、cache、mobile、common
- **代码总量**: 约 300KB+
- **性能瓶颈识别**: 
  - Shader 文件分析耗时较长
  - 符号查找和缓存机制效率有待提升
  - 存在未使用的模块增加加载开销
  - 重复代码导致不必要的计算
  - 复杂的嵌套循环和条件判断影响执行速度

### 优化目标
本次优化**重点关注性能提升**，暂不考虑内存占用问题。核心目标包括：
1. 减少 Shader 分析时间
2. 提升语法解析速度
3. 优化符号查找和缓存机制效率
4. 降低算法复杂度
5. 减少函数调用开销

## 需求

### 需求 1: 优化符号缓存机制性能

**用户故事**: 作为一名性能工程师，我希望优化符号缓存的读写和查找性能，以便显著减少符号解析和查找的耗时。

#### 验收标准

1. WHEN 分析符号缓存的读写操作 THEN 系统 SHALL 识别性能瓶颈点
2. WHEN 优化缓存数据结构 THEN 系统 SHALL 使用更高效的数据结构（如 Map 替代对象字面量）
3. WHEN 实现增量缓存更新 THEN 系统 SHALL 只更新变化的部分而非全量重写
4. WHEN 优化符号查找算法 THEN 系统 SHALL 使用索引或哈希表加速查找
5. WHEN 优化完成后 THEN 系统 SHALL 确保符号查找速度提升至少 30%

---

### 需求 2: 优化语法解析器性能

**用户故事**: 作为一名性能优化者，我希望提升语法解析器的执行效率，以便减少 Shader 文件的分析时间。

#### 验收标准

1. WHEN 分析语法解析流程 THEN 系统 SHALL 识别耗时最长的解析步骤
2. WHEN 优化正则表达式 THEN 系统 SHALL 缓存编译后的正则对象并优化正则模式
3. WHEN 优化字符串处理 THEN 系统 SHALL 减少不必要的字符串拼接和分割操作
4. WHEN 优化循环逻辑 THEN 系统 SHALL 减少嵌套循环层级和循环内的重复计算
5. WHEN 优化完成后 THEN 系统 SHALL 确保语法解析速度提升至少 25%

---

### 需求 3: 清理未使用的模块和代码

**用户故事**: 作为一名插件维护者，我希望移除未使用的模块和冗余代码，以便减少代码加载和执行开销。

#### 验收标准

1. WHEN 扫描项目代码 THEN 系统 SHALL 识别完全未被引用的模块文件（如 `html.ts`）
2. WHEN 分析函数调用链 THEN 系统 SHALL 识别从未被调用的函数和方法
3. WHEN 删除未使用代码 THEN 系统 SHALL 确保编译通过且功能正常
4. WHEN 清理完成后 THEN 系统 SHALL 减少插件启动时间至少 10%

---

### 需求 4: 优化重复代码和算法复杂度

**用户故事**: 作为一名代码审查者，我希望识别并优化重复代码和高复杂度算法，以便减少不必要的计算开销。

#### 验收标准

1. WHEN 扫描代码库 THEN 系统 SHALL 识别功能相似或重复的代码片段
2. WHEN 发现重复代码 THEN 系统 SHALL 提取为公共函数避免重复执行
3. WHEN 分析算法复杂度 THEN 系统 SHALL 识别 O(n²) 或更高复杂度的算法
4. WHEN 优化算法 THEN 系统 SHALL 降低算法复杂度（如使用哈希表将 O(n²) 降为 O(n)）
5. WHEN 优化完成后 THEN 系统 SHALL 确保关键路径执行时间减少至少 20%

---

### 需求 5: 优化 Worker 线程实现

**用户故事**: 作为一名性能优化者，我希望评估并优化 Worker 线程的实现，以便充分利用多线程提升解析性能。

#### 验收标准

1. WHEN 检查 `symbolParserWorker.ts` 的使用情况 THEN 系统 SHALL 确认其是否被正确启用
2. IF Worker 线程未被正确使用 THEN 系统 SHALL 修复实现以启用多线程解析
3. IF Worker 线程开销大于收益 THEN 系统 SHALL 移除 Worker 改用优化的同步解析
4. WHEN 优化完成后 THEN 系统 SHALL 确保大文件解析性能提升至少 40%

---

### 需求 6: 优化文件读写操作

**用户故事**: 作为一名 I/O 优化专家，我希望优化文件读写操作，以便减少磁盘 I/O 带来的性能损耗。

3. WHEN 优化文件读取 THEN 系统 SHALL 实现按需读取和流式读取
4. WHEN 优化完成后 THEN 系统 SHALL 确保文件操作耗时减少至少 30%

## 技术约束

1. **向后兼容性**: 所有优化不得破坏现有功能
2. **性能要求**: 优化后性能必须显著提升，不得出现性能退化
3. **TypeScript 版本**: 保持 TypeScript 5.3.3
4. **VS Code API**: 兼容 VS Code 1.87.0+
5. **测试覆盖**: 关键功能需要保持或增加测试覆盖率
6. **代码可读性**: 性能优化不得以牺牲代码可读性为代价

## 性能优化成功标准

### 核心性能指标

1. ✅ **Shader 分析时间减少 30-40%**
   - 小文件（<500 行）：分析时间 < 100ms
   - 中等文件（500-2000 行）：分析时间 < 500ms
   - 大文件（>2000 行）：分析时间 < 2s

2. ✅ **符号查找速度提升 30-40%**
   - 单次符号查找：< 10ms
   - 批量符号查找（100 个）：< 100ms

3. ✅ **插件启动时间减少 20-30%**
   - 冷启动时间：< 1s
   - 热启动时间：< 300ms

4. ✅ **语法解析速度提升 25-35%**
   - 1000 行代码解析：< 200ms

5. ✅ **文件操作耗时减少 30%**
   - 缓存文件读取：< 50ms
   - 缓存文件写入：< 100ms

### 次要指标

6. ✅ 代码体积减少 10-15%（通过移除冗余代码）
7. ✅ 编译时间减少 5-10%
8. ✅ 所有现有功能正常工作
9. ✅ 代码质量评分提升（ESLint 0 errors）
10. ✅ 算法复杂度降低（关键路径从 O(n²) 降至 O(n) 或 O(log n)）

## 附录：已识别的性能优化点

### A. 高优先级优化点

1. **符号缓存机制**
   - 当前问题：使用对象字面量，查找效率低
   - 优化方案：改用 Map 数据结构，建立索引
   - 预期提升：30-40%

2. **正则表达式优化**
   - 当前问题：每次都重新编译正则表达式
   - 优化方案：缓存编译后的正则对象
   - 预期提升：20-30%

3. **重复代码消除**
   - 当前问题：多处重复的解析逻辑
   - 优化方案：提取公共函数
   - 预期提升：15-25%

### B. 中优先级优化点

4. **未使用模块清理**
   - `src/hlsl/html.ts` - 未被引用
   - `src/cache/symbolParserWorker.ts` - 可能未启用

5. **算法复杂度优化**
   - 识别 O(n²) 的嵌套循环
   - 使用哈希表优化查找

6. **文件 I/O 优化**
   - 实现批量写入
   - 使用异步 I/O

### C. 低优先级优化点

7. **模块导入优化**
   - 清理未使用的 import
   - 实现延迟加载

8. **条件判断简化**
   - 减少嵌套层级
   - 使用查找表替代复杂分支

### D. 性能监控工具

- 添加关键路径的性能计时
- 建立性能基准测试套件
- 集成性能回归测试
